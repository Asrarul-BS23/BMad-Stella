# What belongs in context.md

Rules for deciding what enters `context.md` and what stays out.

## The test

A line earns its place when it saves the agent a search on most tickets and nothing it already loads says it. `stella-build` loads `context.md` together with `_bmad-output/stella/memory/domain-map.md` and `_bmad-output/stella/memory/patterns.md`, and every session loads `CLAUDE.md` and rule files. A line that repeats any of them is paid twice.

## Facts, not rules

`context.md` describes; it does not instruct. Rules live in the team's `CLAUDE.md` and in each developer's memory, and two sources of rules disagree sooner or later. A fact cannot contradict a rule.

- Fact: "`src/generated/` is generated by `pnpm codegen`." Rule: "Never edit `src/generated/`."
- Fact: "The schema is database-first; changes are SQL applied outside the repo." Rule: "Do not add migrations."

Write the fact. The reader's own rules decide what to do with it.

## Admit

- Where each kind of thing lives, when the folder name does not make it obvious.
- Other repos beside the main one, and the file that connects to each.
- Generated folders and what generates them.
- Dead or excluded code, and where the live version is.
- How the schema changes, when that happens outside the repo.
- Layers and what each may reference, read from the project references.
- One recent, complete example file per kind of thing a ticket adds.

## Exclude

|                                                                           | Why                                        |
| ------------------------------------------------------------------------- | ------------------------------------------ |
| Instructions, policy, conventions, pitfalls                               | rules belong to the team and the developer |
| Business purpose, entities, statuses, business rules                      | `memory/domain-map.md` holds them          |
| Base classes, shared utilities, attributes                                | `memory/patterns.md` holds them            |
| Anything in `CLAUDE.md`, `AGENTS.md`, rule files or domain-knowledge docs | already loaded or already read             |
| Stack lists, directory trees, file inventories                            | one look at the code shows them            |
| People, owners, reviewers                                                 | they change                                |
| Pasted code, history, plans                                               | stale immediately                          |

## Accuracy

- Every path is checked to exist before it enters the file.
- A fact with "only", "none", "every" or a specific value is written only after reading the line that proves it.
- Code beats any doc. When a doc disagrees with the code, the code's version is written.

## Size

At most 60 lines. Over budget means the weakest line goes.
