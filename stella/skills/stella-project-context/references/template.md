# File shape

One file: `{project-root}/_bmad-output/stella/project-context/context.md`, at most 60 lines.

**Facts only.** Every line states what exists or how things connect. No instruction, no "never", "always", "must", "should" or "don't": rules belong to the team's `CLAUDE.md` and each developer's own memory, and a fact here can never contradict them.

**Only what is not already known.** Leave out anything in `CLAUDE.md`, `AGENTS.md`, rule files, `_bmad-output/stella/memory/` or `_bmad-output/stella/domain-knowledge/`. Leave out anything one look at the code shows: stack, directory trees, base classes, attributes.

Every path exists at the verified commit. Omit a section with nothing to say.

Line 1 is the provenance line:

```
<!-- Verified YYYY-MM-DD against <short sha>. Managed by stella-project-context; refresh re-verifies every line. -->
```

Without git, `<short sha>` is `none`.

## Sections, in this order

```
# <Project name>

## Where things are
```

One line per area: the folder where each kind of thing lives, and the entry file when one matters. Also, one line each: other repos beside the main one and what connects to them; generated folders and what generates them; dead or excluded code and where the live version is; how the schema changes, when that is not in the repo.

```
## Layers
```

A table: layer, path, what it may reference. Taken from the project references, nothing else.

```
## Copy the shape from
```

One existing path per kind of thing a ticket adds: controller, command, query, entity and configuration, API endpoint, job, test. The newest complete example, not the oldest.
